## Risks

- The spec names normalized evidence sources but not a wire shape. Keep the boundary closed and declarative: source kind determines authority, evidence state is explicit, and the pure kernel never infers risk from prose, labels, paths, or runtime-specific objects itself.
- Semantic evidence must be able to add risk without becoming a negative oracle. Resolve each confirmed item monotonically and never model a semantic `ruled-out` item as subtraction from an authoritative confirmed item.
- Capability names beyond the five immutable gates belong to child workflows. Provide a generic graph contract and prerequisite resolver here; do not encode what project creation, issue delivery, or direct tasks do.
- The graph can be malformed even when selected nodes look valid. Validate duplicate IDs, consumers, profiles, triggers, missing prerequisites, cycles, and the complete immutable set before returning any enabled capability list.
- Warden's tracked mirror is still an interim single-plugin bundle. Byte equality and local imports protect this issue's slice; NOT-551 remains responsible for source hashes, every participating plugin, isolated-install fixtures, and full runtime parity.

## Out of scope

- Natural-language or provider-specific risk detection inside the kernel; adapters normalize explicit metadata, Linear labels, approved specs, repository rules, affected paths, and semantic analysis.
- Domain-specific behavior for project-creation, issue-delivery, or direct-task capabilities.
- Decision manifests, run persistence, content/policy hashes, handoff reuse, or optimistic state revisions (NOT-550).
- General bundle generation for all participating plugins, independent-install tests, hooks/fallbacks, or complete Claude Code/Codex parity (NOT-551).
- New runtime dependencies, Warden ownership of domain artifacts, external-service mutation, committing/pushing outside Git Gremlin, automatic merge, or marking NOT-549 complete.
