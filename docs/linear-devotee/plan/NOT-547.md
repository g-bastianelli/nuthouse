# Plan — Implement configuration resolution and Warden mode controls (NOT-547)

## Context

NOT-547 delivers the first executable slice of the adaptive cross-runtime workflow kernel: validated profile configuration, isolated expiring worktree overrides, and the `warden:mode` control surface. The approved policy spec is authoritative; the interfaces must remain narrow enough for NOT-548/NOT-549 to add classification, risk floors, and capabilities without changing configuration semantics.

## Files

- `_shared/workflow/src/configuration.mjs` — define profiles, strict versioned configuration validation, layer loading/precedence, structured diagnostics, and the extensible mode-status projection.
- `_shared/workflow/src/worktree-overrides.mjs` — derive worktree identity from Git, atomically persist 24-hour overrides under the common directory, expire them safely, and reset only the current worktree.
- `_shared/workflow/src/index.mjs` — expose the stable configuration and override API consumed by later kernel issues.
- `_shared/workflow/tests/configuration.test.mjs` — cover defaulting, precedence, exact-field errors, personal fallback, and status projection.
- `_shared/workflow/tests/worktree-overrides.test.mjs` — cover real-worktree isolation, the exact expiry boundary, atomic persistence, and scoped reset.
- `scripts/build-workflow-config.mjs` — copy only the NOT-547 canonical slice into Warden as an interim installable bundle.
- `scripts/check-workflow-migration.mjs` and `scripts/tests/workflow-migration.test.mjs` — preserve existing migration checks while requiring byte-identical Warden mirrors and manifest parity.
- `package.json` — expose the narrow build/check commands without adding dependencies.
- `warden/lib/workflow/{configuration,worktree-overrides,index}.mjs` — tracked install-local mirror so Warden never imports repository-only `_shared` sources at runtime.
- `warden/scripts/mode.mjs` — implement an injectable JSON CLI for `quick`, `standard`, `strict`, `status`, and `reset`.
- `warden/tests/mode.test.mjs` — verify CLI reports, invalid-config behavior, expiry, and reset isolation.
- `warden/tests/skill-contracts.test.mjs` — verify the public skill arguments, command routing, report fields, and safety constraints.
- `warden/skills/mode/SKILL.md` and `warden/skills/mode/agents/openai.yaml` — add the scaffolded cross-runtime Warden client with no subagent or domain ownership.
- `warden/.claude-plugin/plugin.json`, `warden/.codex-plugin/plugin.json`, `warden/README.md`, and `CLAUDE.md` — bump the Warden release metadata and document mode control separately from voice control.

## Risks

- The spec fixes the repository path but not the personal path. Keep the canonical resolver path-injected and make `~/.nuthouse/workflow.json` only the Warden adapter default so later runtime adapters can choose another local source without changing policy.
- Expiry cleanup is a mutation. Repository validation must complete first; an invalid repository configuration returns the exact blocking field without writing, deleting, or masking state.
- The Warden mirror is intentionally narrow and temporary. A byte-equality check prevents divergence now; NOT-551 remains responsible for source hashes, all participating bundles, independent-install fixtures, and full Claude/Codex adapter parity.
- AC-011 names risk/capability output whose computation belongs to NOT-549. This issue stabilizes the status shape and truthful empty defaults, without adding profile ranking, risk evidence, immutable gates, or capability logic.

## Out of scope

- Workflow classification or `warden:route` (NOT-548).
- Risk floors, escalation computation, immutable gates, or capability resolution (NOT-549).
- Decision manifests, handoff reuse, policy-hash validation, or optimistic manifest concurrency (NOT-550).
- General all-plugin bundle generation, source hashes, install-isolation fixtures, hook fallbacks, or complete runtime parity tooling (NOT-551).
- Domain workflow behavior, project-owned `.nuthouse/workflow.json` creation, personal-preference mutation, voice-state changes, dependency additions, merge automation, or Linear completion.
