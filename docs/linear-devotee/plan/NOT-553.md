## Risks

- The current Maestro issue description names removed `run`/`advance` skills; the live project architecture exposes `orchestrate` and `spawn` as the two worktree-creation paths. Integrate the relay baton there and update the shared execution contract instead of resurrecting legacy entry points.
- A workflow manifest is scoped to its producing worktree. Relay propagates the parent run/profile/decision identity as an immutable baton to the new worker prompt; it must not pretend the parent manifest is a valid child-worktree manifest or bypass the child's install-local validation/resolution.
- `RELEVANT_FILES` hashes are pre-implementation provenance for mutable targets, not post-edit invariants. Verification preserves their path set, rebinds their final hashes, and binds command results to an index-independent `HEAD_OID` plus working-tree snapshot that Git delivery must recheck.
- The manifest handoff schema is closed to `run_id`, `path`, and `content_hash`; carry `effective_profile` beside it and recover missing direct-entry context through one install-local resolution. Commit additionally rechecks the staged index's content, type, and canonical mode because the worktree snapshot intentionally excludes staging-only changes.
- The approved child spec has no matching Acid Prophet project-level plan in this repository. Record `_none_` and implement exact-reference discovery for future projects; do not promote prior issue plans or the parent kernel spec into an invented project implementation plan.
- Acid Prophet checklist generation is evidence derivation, not feature acceptance. Keep the checklist open and preserve its review/PR-comment choices; no checked item can authorize merge or Linear completion.
- These plugins are declarative skill programs, so cross-plugin contract tests inspect their normative workflow language and ordering. Preserve existing runtime helper boundaries and add pure code only if a contract cannot be expressed or verified at the skill boundary.

## Out of scope

- Changing the parent workflow kernel, manifest schema/store, classifier, risk lattice, capability graph, generated workflow bundles, or ratified Acid Prophet specs.
- Reintroducing Monkey Maestro `run`/`advance`, replacing Linear scheduling authority, changing issue dependencies/lifecycle beyond greet's authorized start transition, or adding a hidden relay queue.
- Automating feature acceptance, PR review approval, branch publication without Git Gremlin confirmation, PR merge, Linear completion, or post-PR relay.
- Adding dependencies, making Warden mandatory, requiring a Moon workspace for verification, pushing/committing/creating or merging a PR, mutating Linear dependencies, or editing unrelated plugins.
