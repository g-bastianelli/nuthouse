# Plan — Persist and validate decision manifests (NOT-550)

## Context

NOT-550 adds the durable decision-manifest slice to the shared adaptive workflow kernel after configuration, classification, risk, and capability resolution were established by NOT-547–NOT-549. The approved parent spec and AC-036–AC-042 are authoritative: manifests carry a closed redacted projection of normalized policy decisions, live under the repository Git common directory, survive plugin handoffs by a hash-bound descriptor, and reject stale or drifting state without implementing the dependent all-plugin bundle/adaptor work owned by NOT-551.

## Files

- `_shared/workflow/src/manifest-schema.mjs` — define the strict version-one manifest and handoff schemas, safe normalized-decision and artifact-reference projections, canonical timestamps/identities/hash formats, content hashing, and structured validation errors.
- `_shared/workflow/tests/manifest-schema.test.mjs` — table-drive valid/invalid schema versions and fields, repository/worktree identity, timestamps and expiry, policy/content hashes, safe artifact path/hash references, canonicalization, and redaction of disallowed raw inputs.
- `_shared/workflow/src/manifest-store.mjs` — derive run paths below the Git common directory, atomically persist canonical JSON, serialize writes with a run-scoped lock, enforce optimistic revisions, and reopen bytes without last-writer-wins behavior.
- `_shared/workflow/tests/manifest-store.test.mjs` — use temporary Git repositories and real linked worktrees to verify path confinement, atomic rename and cleanup, exact byte hashes, initial/update revisions, sibling-worktree scope rejection, and stale concurrent writer conflicts.
- `_shared/workflow/src/workflow-resolution.mjs` — provide the canonical successful-resolution boundary that composes `resolveWorkflowPolicy`, rejects ambiguous/blocked output, and always persists the resulting manifest before returning its handoff.
- `_shared/workflow/tests/workflow-resolution.test.mjs` — prove a successful normalized resolution writes exactly one manifest while ambiguous/blocked resolution writes none.
- `_shared/workflow/src/manifest-handoff.mjs` — create and consume the exact `run_id`/path/content-hash handoff, reuse valid manifests without invoking classification, reject policy drift, and permit exactly one injected authoritative local re-resolution for recoverable invalid states.
- `_shared/workflow/tests/manifest-handoff.test.mjs` — cover valid reuse, missing/expired/corrupt/out-of-scope rejection, one-call re-resolution, ambiguity/disagreement blocking, path/hash tampering, and exact `runtime-drift` behavior.
- `_shared/workflow/src/index.mjs` — export the stable manifest schema, persistence, and handoff APIs from the canonical kernel.
- `scripts/build-workflow-config.mjs`, `scripts/check-workflow-migration.mjs`, and `scripts/tests/workflow-migration.test.mjs` — extend only the existing interim Warden byte mirror so the repository's current workflow gate remains green; do not implement generalized bundle generation, source-hash metadata, runtime adapters, or install-isolation fixtures.
- `warden/lib/workflow/{manifest-schema,manifest-store,workflow-resolution,manifest-handoff,index}.mjs` — generated byte-identical interim mirrors required by the existing migration gate until NOT-551 replaces that bridge.
- `warden/.claude-plugin/plugin.json` and `warden/.codex-plugin/plugin.json` — keep the paired patch version aligned for the mechanically changed shipped Warden mirror.

## Risks

- The spec intentionally names required manifest properties without prescribing the full wire shape, but it does prescribe `run_id` for handoffs and names artifact paths as allowed manifest data. Keep version one minimal and closed: identities, normalized enum policy decisions, path/hash-only artifact references, hashes, revision, and timestamps; use exact `{ run_id, path, content_hash }` at the handoff boundary.
- A policy hash represents the participating bundle's policy version and must be supplied by the caller; deriving it from the selected decision would fail to detect two runtimes executing different policy code. NOT-551 remains responsible for generating and embedding canonical bundle source hashes.
- A content hash covers the exact canonical UTF-8 bytes written to disk and is carried outside the manifest in the handoff, avoiding a self-referential hash field. The manifest still records the independent producer policy hash.
- Atomic rename alone does not provide compare-and-swap semantics. The run-scoped exclusive lock must cover read/compare/write, recover only provably abandoned owners, and recheck revision after acquisition so a stale writer cannot replace a newer manifest.
- Missing/expired/corrupt/out-of-scope state is recoverable once; policy drift is not. Keep these branches explicit so the fallback cannot conceal mismatched bundles or recursively resolve.
- The tracked Warden mirror is an existing temporary compatibility bridge. Update it mechanically so current repository checks pass, but leave general source-hash generation, all participating plugin bundles, install-isolation tests, runtime adapters, hooks, and fallback wiring to NOT-551.

## Out of scope

- General bundle generation or canonical source-hash metadata for Acid Prophet, Linear Devotee, Moon Moth, Git Gremlin, Monkey Maestro, and Warden (NOT-551).
- Claude Code/Codex runtime adapters, hook acceleration, explicit-skill fallback wiring, independent-install isolation, or domain-plugin handoff integration (NOT-551 and child workflow issues).
- Domain behavior or artifact contents for project creation, issue delivery, and direct tasks; manifests may carry only validated artifact id/path/content-hash references, never full prompts, source code, secrets, Linear issue bodies, complete logs, or arbitrary free-form fields.
- Changes to the authoritative Acid Prophet spec, package dependencies, unrelated plugins, external-service mutation beyond the already-authorized greet status transition, commits/pushes, PR creation/merge, or marking NOT-550 complete.
