# Plan — Implement deterministic classification and Warden routing (NOT-548)

## Context

NOT-548 adds the deterministic classification slice of the adaptive workflow kernel and exposes it through an optional, read-only `warden:route` client. The approved parent spec and the issue-local AC-001–AC-004 are authoritative; the human clarification on 2026-08-28 makes explicit Linear-project intent language-independent, so adapters normalize that semantic signal before the pure kernel classifies it. This delivery returns a route descriptor only and leaves domain execution, risk policy, manifests, and general bundle distribution to their owning issues.

## Files

- `_shared/workflow/src/classification.mjs` — define the normalized, language-independent project-intent signal, Linear issue-id extraction, deterministic conflict rules, and the four-value classifier.
- `_shared/workflow/tests/classification.test.mjs` — table-drive caller-normalized multilingual project intent, request/branch issue signals, direct tasks, duplicate identifiers, incompatible/uncertain signals, and purity/no-mutation behavior.
- `_shared/workflow/src/index.mjs` — expose the classifier contract through the canonical kernel entry point.
- `scripts/build-workflow-config.mjs` — extend the existing interim Warden copy build with the canonical classifier module without generalizing all-plugin packaging.
- `scripts/check-workflow-migration.mjs` and `scripts/tests/workflow-migration.test.mjs` — require the new Warden classifier mirror and fail on missing or stale bytes.
- `warden/lib/workflow/{classification,index}.mjs` — keep the install-local Warden bundle byte-identical to the canonical classifier and exports.
- `warden/scripts/route.mjs` — consume the adapter's normalized `explicit | absent | ambiguous` project intent plus task/branch issue evidence, classify it with Warden's local bundle, and return one explicit target union: a Linear Devotee skill target, a current-turn direct-task continuation, or no target for blocked ambiguity.
- `warden/tests/route.test.mjs` — verify route mappings, branch-only issue delivery, deterministic ambiguity, CLI exit behavior, injected Claude/Codex-equivalent inputs, and absence of repository writes or owner execution.
- `warden/skills/route/SKILL.md` and `warden/skills/route/agents/openai.yaml` — publish the scaffolded cross-runtime `warden:route` client, normalize explicit project intent semantically in the user's language, and make uncertain intent plus ambiguity/no-domain-mutation stops explicit.
- `warden/tests/skill-contracts.test.mjs` — enforce the route argument, local-bundle client, owner mappings, and safety boundaries alongside the existing mode contract.
- `warden/.claude-plugin/plugin.json`, `warden/.codex-plugin/plugin.json`, `warden/README.md`, and `CLAUDE.md` — release and document routing while preserving matching runtime metadata and Warden's optional ownership boundary.

## Risks

- AC-001 contains mixed-language wording, while the human decision requires language independence. Model project creation as the closed normalized signal `explicit | absent | ambiguous`; adapters interpret the user's language, the kernel never embeds a phrase dictionary, and uncertainty becomes `ambiguous` rather than a guessed workflow. This accepted clarification is spec drift to sync only after plan validation.
- A request and branch may repeat the same issue identifier or name different issues. Normalize case and deduplicate the same identifier; classify multiple distinct identifiers conservatively as `ambiguous` rather than selecting one by source precedence.
- The current feature branch itself contains `NOT-548`, so direct-task and project-only fixtures must inject neutral branch context; integration coverage must also prove branch-only issue delivery.
- `warden:route` can expose a target but must not execute it in this issue. Use a closed target union: Linear Devotee skill targets for project/issue workflows, `{ kind: "current-turn", name: "direct-task" }` for the direct pipeline defined by its child spec, and `null` for ambiguity. This avoids inventing a direct-task plugin owner and keeps ambiguity observably inert.
- The current Warden mirror is an interim single-plugin bundle. Byte-equality checks cover this classifier slice, while NOT-551 remains responsible for hashes, all participating plugins, independent-install fixtures, hooks, and complete runtime parity.
