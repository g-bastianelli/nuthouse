strict JSON example omitted required issue fields, and graph equality could permit execution
despite changed Acceptance text under the same id. Both were corrected in prose. The reviewer
extracted the corrected example from Markdown and verified it with the existing graph helper;
it validated and compared equal. The caller requires matching written fields as well as
graph equivalence. Confirmed project absence is distinct from an
incomplete read during recovery.

The existing hook/graph tests (51), repository metadata/parity tests (105), and persona-hook
tests (24) all passed. Lint, formatting, generated-agent parity, runtime parity, plugin invariants,
prose duplication, manifest parsing, and diff whitespace checks passed. A test that only
searched greet prose for exact phrases was removed; runtime
startup/resume/compaction behavior remains exercised by the existing executable hook tests.
No runtime script was added for the skill refactor.

## Proportional workflow follow-up

The follow-up targets unnecessary stages rather than a script-count limit. A small conventional
issue plan can use a local review against the existing auditor criteria; material uncertainty,
interacting tasks, new boundaries, or an explicit request still call for independent review.
Applicable review evidence is reused while its inputs remain valid.

A fresh forward run in `linear-devotee-eval-eEUPLz` used the same existing-plan revision fixture.
It produced validated version 3, retained completed T0 and pending T1, preserved exact AC-001
scope, and specified the complete entry-point regression and guard-precedence checks. The
review was honestly labeled local. No reviewer was dispatched and the already delegated
validation required no additional approval. The plan and final response contained a complete
handoff. This run inspected source without executing the defect or future tests, and did not
claim otherwise.

Project creation now approves the complete cascade, including a proposed source register,
together. Unresolved product decisions still require answers before dependent work. The
existing envelope validator already validates its embedded graph, so the duplicate graph
validation step was removed. One authoritative reload supplies both graph and written-field
verification. An unused verification-receipt comment was removed after checking that no
workflow consumed it; matching actual written fields and graph remains required.

These changes reduce required stages in the instructions. The local-review run demonstrates
one shorter execution path; no latency benchmark or general speedup is claimed.

## Limits

These are bounded observations, not a success rate or a comparison with other skill collections.
The project-drafter was evaluated offline; full provider creation, normalization, permissions,
and ambiguous-timeout recovery were not exercised against a live Linear workspace. Structural
graph tests and a contract review do not establish those external integration outcomes.
