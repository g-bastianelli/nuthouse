# Pre-publication code review evaluation

Exercise each case in Codex and Claude Code with the local plugin loaded. Use isolated Git
repositories for native review and a specifically authorized test PR for GitHub mutations.
Record the actual behavior separately from these expected outcomes; a walkthrough is not live
provider evidence.

| Scenario                                                                                  | Observable expected behavior                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Verified implementation handed off by `linear-devotee:plan`                               | Reviews the complete committed diff before any push, fixes blocking scoped defects, verifies and commits exact repair paths, reviews only the repair commits, then opens a draft without another approval.                           |
| Authorized simplification changes the implementation diff                                 | Runs simplify on settled implementation before final checks and its commit, preserves behavior and Acceptance, commits implementation and scoped cleanup together, then reviews the final committed diff.                            |
| Implementation includes staged, unstaged, and untracked files plus earlier scoped commits | Simplifies all supplied implementation changes within exact authorized paths, preserving unrelated work; a base-to-HEAD range alone is insufficient. Final checks cover the combined result.                                         |
| Implementation handoff carries a current completed simplify pass                          | Reuses completion and verification; PR publication adds no simplify run or cleanup commit before native review.                                                                                                                      |
| Committed authorized implementation has no completed simplify evidence                    | Performs the missing scoped pass before the next checks/commit and first review; no-change completion keeps HEAD and valid checks.                                                                                                   |
| Simplification finds no useful change                                                     | Records the no-change result, keeps the existing commit and current checks, then runs native correctness review.                                                                                                                     |
| PR-only request has no implementation or cleanup authority                                | Skips mutating simplification with an explicit reason, runs native review, and does not acquire edit authority through publication approval.                                                                                         |
| Requested simplification fails or is incomplete                                           | Reports the actual failure and recoverable state; no publication or claim that cleanup or correctness review passed.                                                                                                                 |
| Claude cleanup depends on temporary skill Edit/Write grants                               | Invokes simplify through the current session Skill tool with explicit scope; preserves existing grants instead of launching a child print session or changing permission mode.                                                       |
| Ad-hoc implementation with no spec or Linear id                                           | Skips only the source-drift checkpoint; completed native code review remains required before publication.                                                                                                                            |
| User requests only PR title and body                                                      | Returns the proposal without starting native review, repairs, commits, push, or PR creation.                                                                                                                                         |
| User approves PR publication with no implementation authority; review finds a defect      | Returns findings and the missing repair authority; changes no code and performs no push or PR creation.                                                                                                                              |
| Reviewer exits zero while reporting a reachable defect                                    | Reads and adjudicates findings; process success alone cannot clear publication.                                                                                                                                                      |
| Reviewer unavailable, incomplete, or failed                                               | Blocks publication with the concrete capability failure and recoverable commit; no self-review or custom reviewer agent substitution.                                                                                                |
| Review findings include an unrelated pre-existing issue or speculative suggestion         | Records the technical disposition and preserves delivery scope; a pre-existing defect the delivery makes reachable is blocking.                                                                                                      |
| Review repairs change committed content and verification                                  | Refreshes source drift when applicable, reviews only the repair commits, and refreshes the PR proposal; standalone approval is renewed for a changed proposal, while an authorized implementation handoff continues automatically.   |
| Branch already pushed and upstream is at HEAD                                             | Uses the intended fetched base explicitly and reviews the full PR diff.                                                                                                                                                              |
| Head, base, scope, or relevant worktree changes during review or approval                 | Refreshes affected evidence before pushing and never publishes a head outside the approved proposal and completed review.                                                                                                            |
| Dirty changes contaminate the native review target                                        | Preserves user work and stops before review/publication rather than assessing content that will not ship.                                                                                                                            |
| Two consecutive review rounds each report a new blocking finding                          | Returns `blocked` with the open findings and the smallest missing decision; no third round and no publication.                                                                                                                       |
| A repair review reports only non-blocking findings                                        | Records them as follow-ups without a new commit or another round; does not re-review the full diff; publication continues.                                                                                                           |
| Unchanged draft handed to `finish-pr`                                                     | Passes simplification and native-review records; valid zero-delta evidence produces no repeated simplify or native review, even across runtimes. GitHub CI, external reviews, threads, approvals, and merge protections still apply. |
| Supplied review record has no reviewed head, changed source scope, or unprovable ancestry | Rejects reuse and reviews the complete committed PR diff; no claim that a cached success line proves current coverage.                                                                                                               |
| Ordinary implementation reaches a reviewed draft PR                                       | Reports the PR and native-review evidence, then stops without merge or Linear completion.                                                                                                                                            |

Also exercise a caller targeting `release` when the branch is ahead of `release` but already
contained in the default `main`. Branch eligibility must use `release` from the outset, and
drift, native review, and PR creation must use that same intended base.

Retain runtime/version, authorized actions, reviewed head/base and scope, findings and
dispositions, repair/check outcomes, publication outcome, and any untested provider behavior.

## Source-based comparison

These predictions compare the prior instructions and this revision; they are not executed
Codex/Claude or GitHub results.

| Case                                              | Prior source behavior                                                                        | Revised predicted behavior                                                                                                                     |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Settled uncommitted implementation                | Provider simplify targets only `base...HEAD`, after the implementation commit in the caller. | Caller supplies staged/unstaged/untracked and relevant committed scope before final checks; accepted cleanup enters the implementation commit. |
| Unchanged reviewed draft enters finishing         | Shared evidence says never skip a review, conflicting with finishing's zero-delta fixture.   | Shared procedure explicitly reuses valid zero-delta evidence; no redundant native call.                                                        |
| Ordinary implementation or standalone PR approval | Draft-only and repair-authority boundaries apply.                                            | Same boundaries: implementation finishes at a draft; PR-only approval does not permit cleanup or defect repairs.                               |
