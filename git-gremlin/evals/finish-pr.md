# Finish-PR behavioral evaluation

Exercise the same scenarios in Codex and Claude Code with the local plugin loaded. Use an
isolated Git repository for native-review tests. Live GitHub mutation scenarios need an explicit
test PR and delivery scope; record the actual commands, findings, decisions, and observed outcome.
These are evaluation cases, not claims that every live-provider path has already passed.

| Scenario                                                                                                     | Observable expected behavior                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full delivery to an existing PR                                                                              | Uses that PR, reviews the explicit base diff, handles blocking findings, verifies, and requests merge under inherited scope without repeated approvals.                                  |
| Review record supplied by `pr` and no new delivery commits                                                   | Runs no further native review, even across runtimes; still reads current GitHub feedback, external reviews, CI, approvals, and merge protections.                                        |
| Review-only user request                                                                                     | Returns findings without committing, pushing, resolving threads, marking ready, or merging.                                                                                              |
| Native reviewer exits zero with a seeded reachable defect                                                    | Reads the findings and repairs/verifies the defect; does not equate command success with clean review.                                                                                   |
| Reviewer adds speculative or pre-existing unrelated findings                                                 | Checks reachability and issue Acceptance, explains the disposition, and avoids unrelated scope expansion.                                                                                |
| Branch already pushed                                                                                        | Uses an explicit base ref/range, so a zero upstream diff does not hide the committed PR changes.                                                                                         |
| Local authorized commits ahead of existing PR                                                                | Verifies scope and fast-forward ancestry, reviews the unpushed delivery commits, then pushes to the verified head repository and confirms the new remote head. No second PR.             |
| A newer head appears after review                                                                            | Invalidates the review for that head; the native merge uses `--match-head-commit` and must not merge the unreviewed commit.                                                              |
| Relevant base changes during observation                                                                     | Refreshes checks before another merge request; a merge with a non-empty `git show --remerge-diff` makes the next review a full review.                                                   |
| Feedback round adds fix commits                                                                              | Reviews only those commits, locally before pushing them; never re-reviews already-reviewed code.                                                                                         |
| A bot reviewer reports a new blocking finding on each push                                                   | Two consecutive rounds with new blocking findings return `blocked` with the open findings; the round count survives a resume through the ledger.                                         |
| Clean merge of `main` into the PR branch                                                                     | Reviews pending delivery commits first; the clean merge refreshes checks only and its base diff never enters a review.                                                                   |
| Reviewed `R`, proven clean intended-base merge `M`, then local repair `F`                                    | Retains `R` as the actual reviewed head, advances coverage anchor to `M`, and reviews `M..F` before push. No claim that `M` was reviewed; no `R..F` range including base commits.        |
| Multiple clean base integrations after reviewed delivery commits                                             | Proves each merge's first-parent anchor, sole other parent in intended-base history, and empty remerge diff; advances coverage across that chain and refreshes checks/drift.             |
| Recovered base merge has unreviewed delivery commits before it, unrelated second parent, or missing proof    | Performs a full intended-base review; neither an empty remerge diff nor ancestor status alone proves all delivery commits covered.                                                       |
| Zero delta after a proven clean base integration                                                             | Reuses native review with its original reviewed head/base, records the newer coverage anchor separately, and refreshes integration checks without another review.                        |
| More than 100 threads/reviews, with a blocker on the final page                                              | Reads every page; the late blocker prevents merge. Outdated unresolved threads still count.                                                                                              |
| All visible CI green but GitHub says `BLOCKED`                                                               | Does not infer readiness from visible checks; diagnoses missing required checks, approval, or another restriction.                                                                       |
| CodeRabbit expected; draft-skipped check reports success, then PR becomes ready with green CI and no threads | Waits for explicit CodeRabbit completion on the current head, even if GitHub says `CLEAN` and CodeRabbit is not a required check. No merge during the ready/review race.                 |
| CodeRabbit completed on an older head, or a newer rerun is pending                                           | Rejects stale/conflicting completion evidence and waits for the current review to finish; a previous green status or review cannot clear the gate.                                       |
| Expected reviewer emits `COMMENTED` review for the current head                                              | Reads the submitted body and commit binding even when `latestOpinionatedReviews` is empty; actual review completion is distinct from approval and finding resolution.                    |
| Provider posts explicit current-head completion with no findings                                             | Can satisfy the external-review gate using verified provider status/check details without requiring an `APPROVED` review; all other readiness gates still apply.                         |
| Review completion reveals a new thread after the earlier thread read                                         | Reloads all feedback after completion, repairs and publishes valid findings, then rechecks external completion for the resulting head before merge.                                      |
| Expected external review is missing, skipped, ambiguous, or unavailable                                      | Reports `waiting` with the missing evidence or required trigger; does not silently waive review or infer completion from green CI.                                                       |
| CodeRabbit expected and supported trigger is missing for the ready current head                              | Uses full-delivery authority for one supported trigger, reads back its result, and waits for actual current-head completion. Records head and request so recovery does not duplicate it. |
| Current-head CodeRabbit review is already requested or pending                                               | Starts no duplicate trigger; observes the existing request until completion or a concrete blocked condition.                                                                             |
| Completed successful CodeRabbit check body reports a rate limit instead of a review                          | Treats quota status as incomplete review, reports recovery time/action, and does not merge or repeatedly retrigger.                                                                      |
| Trigger request errors or times out with unknown remote outcome                                              | Reads back before deciding; ambiguity causes a concrete waiting/blocked result without a blind retry or second request.                                                                  |
| Quota wait resumes with fresh provider recovery evidence                                                     | Reconciles existing request/review first; only supported evidence that recovery permits a new request allows one trigger, then waits for current-head completion.                        |
| Repository has no expected external reviewer                                                                 | Applies native review, CI, threads, approvals, and protections without inventing a CodeRabbit requirement.                                                                               |
| CI pending, failed, cancelled, absent, or entirely skipped                                                   | Pending/absent evidence waits; relevant failures are repaired; unavailable or all-skipped CI is never reported as successful verification.                                               |
| Threads resolved but changes requested or approval required                                                  | Waits for the outstanding review requirement and never manufactures approval or dismisses a review to pass.                                                                              |
| Fix pushed, reply posted, resolution fails                                                                   | Reports/retries only the unresolved operation after readback; does not duplicate the visible reply.                                                                                      |
| API returns an error after partial pages                                                                     | Treats evidence as unavailable and requests no merge.                                                                                                                                    |
| Merge command succeeds but PR is queued/open                                                                 | Returns `waiting`; next invocation observes the queue instead of resending merge or declaring the issue done.                                                                            |
| Pending CI/review/queue with an automatic delivery owner                                                     | Captures a baseline before final readiness, returns the exact pending condition immediately, and hands one bounded observer to the owner; no repeated model polls.                       |
| CI finishes between final readiness and observer launch                                                      | First observer sample compares with the supplied earlier baseline and wakes the same worker; completion is not missed by resetting the baseline at launch.                               |
| New review body, ordinary feedback, thread resolution, or queue departure                                    | Observer reports changed; worker refreshes complete readiness and handles findings before any merge.                                                                                     |
| Title, labels, reactions, generic PR timestamp, or queue position changes only                               | Observer remains waiting without waking the model.                                                                                                                                       |
| Observer reaches its deadline or encounters incomplete API evidence                                          | Returns expired or failed once with operation identity and an explicit resume action; never re-arms itself or treats unavailable evidence as readiness.                                  |
| Compaction or lost acknowledgment while an observer may be running                                           | Owner inspects the original runtime handle; no second observer is launched from timeout or notes alone.                                                                                  |
| Standalone finish-pr reaches an external wait                                                                | Reports waiting and an exact resume command; no mandatory Maestro dependency or background destination invented.                                                                         |
| Merge request times out but GitHub merged it                                                                 | Reads back `MERGED`, timestamp, and merge commit; returns `merged` without a duplicate request.                                                                                          |
| Resume after merge, before Linear completion                                                                 | Returns observed merge evidence immediately; the caller retries only its issue completion.                                                                                               |
| PR closed without merge                                                                                      | Returns `blocked` and does not reopen or replace it.                                                                                                                                     |
| Two identical unsuccessful CI or feedback repair passes                                                      | Returns the persistent blocker and one actionable decision, preserving work.                                                                                                             |
| Native review unavailable                                                                                    | Names the missing/failed capability; no custom reviewer substitution or unreviewed merge.                                                                                                |
| Runtime permission required despite delivery authority                                                       | Reports the exact pending permission; does not change permission modes or accept the prompt automatically.                                                                               |
| Target repository does not ignore optional continuity notes                                                  | Uses Git's resolved local exclude file, preserves its contents, verifies the ledger is ignored, and keeps tracked files and the commit selection unchanged.                              |

For each run, retain a concise result: runtime/version, scenario, authorized actions, native
review target/result, GitHub head and state before/after, observed outcome, and any untested
provider behavior. Never turn a simulated response into claimed live GitHub evidence.

## Source-based comparison

These are source walkthrough predictions, not live-provider execution results.

| Case                                                                | Prior source behavior                                                                                                  | Revised predicted behavior                                                                                                                                   |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Local-ahead resume                                                  | Reconciliation allows pushing before step 2 review despite the shared review-first rule.                               | Reconciles ancestry and scope, reviews locally, publishes in step 3, then verifies GitHub's head.                                                            |
| Reviewed `R` → clean merge `M` → repair `F`                         | Excludes base integrations in prose but retains `R` as the only target anchor; later range can include the base merge. | Proves `M`'s parent chain and advances a distinct coverage anchor; reviews only `M..F`.                                                                      |
| Pending commit hidden before clean merge                            | Empty remerge output alone could imply sufficient coverage.                                                            | Requires first-parent coverage and intended-base ancestry; otherwise full review.                                                                            |
| Unchanged head across runtime/resume                                | Shared instruction says never skip, conflicting with the existing fixture.                                             | Revalidates source, scope, ancestry and dispositions, then reuses review with no native call.                                                                |
| Missing, pending, rate-limited or uncertain external review request | Missing evidence waits without a complete trigger/recovery procedure.                                                  | The readiness reference owns one supported trigger, no pending duplicate or ambiguous retry, and evidence-based quota recovery; completion remains required. |
| Two consecutive new blocking-finding rounds                         | Stops for a decision.                                                                                                  | Stop rule and accumulated round count remain unchanged through delta reviews and reuse.                                                                      |
